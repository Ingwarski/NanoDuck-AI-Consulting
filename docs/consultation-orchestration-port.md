# Head-led consultation port brief

23 September 2026. This is a reusable implementation prompt for the two sister repositories: Neo and the separately hosted sister. It incorporates the consultation repair implemented in `8a63a7c`. It contains no private consultation transcript, account identifiers, credentials or machine paths. This checkout is the reference implementation; this document does not authorize changes to either sister repository.

## Prompt to use in each sister repository

Inspect that repository's own `AGENTS.md`, Git root, current SDD sources, runtime and hosting contract before editing. Apply the behavior below to its actual modules; do not copy local-only TLS, storage or process assumptions into a hosted system. Keep its approved visual baseline, authentication, data-protection and provider/billing boundaries. Reconcile its own product idea → PRD → context/terms → affected design/architecture → DoD → QA → development plan through the installed SDD pipeline and checker. Treat this brief as the desired change, not as authority over that repository's confirmed product sources. Implement, test, inspect the diff and commit only in the selected sister repository.

1. Make Head Consultant the actual AI orchestrator. Head reads the entire ordered owner request and later corrections, records each requested deliverable, selects the **actual permitted specialist roles** within the owner-selected team size, writes a distinct considered assignment for each and decides after a whole-team review whether another targeted round is useful. The application backend validates roster identity/count, persists decisions, routes messages, enforces security and handles Stop/Continue; it is not another AI orchestrator or a keyword selector of roles.
2. Commit and deliver every successful Head task **verbatim** to its named specialist. Remove XML/task wrappers, imperative-word checks, forced case-anchor/two-detail rules, sentence and 420-character bounds, corrective retries for ordinary task wording, and all generic replacement briefs. Migrate exact former public prompt defaults in encrypted saved instructions so restarts do not revive the wrapper or answer cap; preserve user-edited sections and prior revisions. A provider failure pauses truthfully; it never fabricates a Head task. Keep owner-input and source-metadata policy checks, tool-transcript rejection and actual secret protection as separate provider/security boundaries.
3. Give every participating agent the same complete ordered owner text, corrections and confirmed discussion, including a direct source ledger, then add that agent's own role and exact Head assignment. Do not use only the last owner message or silently slice the tail of discussion. If image pixels cannot reach a text-only provider, state that limitation explicitly instead of implying the attachment was analyzed.
4. Let Critic issue a targeted **stop-and-rework** directive for circular, irrelevant, fabricated or unsupported consultant work. Critic checks the entire owner request, requested deliverables, the exact Head assignment, source evidence, numerical claims and contradictions; it must call out obvious nonsense and false certainty with the specific claim/omission, why it fails and what evidence, calculation or direct answer is needed. It must not invent a defect in sound work. The consultant must materially revise, raise a specific evidence-based objection or acknowledge unavailable evidence. Head sees and arbitrates this exchange. Critic checks every requested output again before declaring final consensus; fluent agreement alone does not prove sound advice. Upgrade exact old public defaults for both the per-specialist Critic challenge and joint final review in saved runtime instructions, including legacy run snapshots; preserve owner-edited sections and their version history. Keep a short code-owned Critic reminder so custom wording cannot remove the evidence-based challenge or requested-output check. Do not build a semantic acceptance gate that rejects Head assignments or an automatic loop that repeats the same criticism.
5. Interpret discussion depth as a **ceiling**, not a mandatory quota. Every selected specialist gets at least one Critic challenge and reply. After each team-wide round, Head either closes or directs another useful round within the selected 1/3/5 ceiling; Auto permits at most 10. Preserve each specialist's final position, a joint Critic review and a single Head conclusion. Unresolved advice is provisional, not claimed consensus. Persist the roster/progress decisions so Stop, Continue, provider failure and restart do not duplicate confirmed messages. For runs saved by the prior coordinator, recover any already committed roster prefix from addressed Head tasks; Head chooses only missing roles, keeping the confirmed tasks intact.
6. Separate public research from private model context. Head forms a minimal public query in a non-web step. Validate the actual outgoing query for contacts, credentials and unsafe destinations. Only that query, with public instructions and no private discussion/guidance, enters the web-enabled step. A phone number elsewhere in the conversation and a numeric identifier in a safe public article URL must not disable safe research. Save every valid direct source URL, title, supported claim and freshness; do not drop sources after an arbitrary eighth item. Allow Critic to surface a targeted evidence gap that Head or a Codex consultant can pursue through this same isolated route. A withheld/failed search remains an explicit evidence limitation, never invented research.
7. Remove arbitrary 32,000-character owner-message, 80,000-character discussion, role-output and 2,000-character final trims. Retain finite HTTP/storage/provider resource ceilings with truthful errors and no silent shortening or provider/model substitution. The final Head answer must cover every distinct requested output, direct source links where available and an explicit account of missing evidence/items. Do not force a three-action limit when the request requires more.
8. Change Settings copy so 1/3/5/Auto review depth is described as a ceiling and Head's decision, while preserving the existing controls and approved layout. Do not introduce a new orchestration screen or visual redesign.
9. Do not stop a viable consultation over one detected Russian/Belarusian fragment in generated prose. Remove the whole guilty sentence before persistence, show a neutral omission marker and keep the useful English/Ukrainian remainder, even when a sentence contains a URL or the response spans lines. Replacing only a matched word can leak the rest of a prohibited sentence. Similarly, remove an unsuitable Markdown or raw URL from generated prose without treating it as a verified source or discarding the surrounding advice; retain a safe link label where useful. Validate cited source records independently and drop invalid source metadata. English descriptors such as “Russian” or “Belarusian” and valid shared Ukrainian words such as `які` are not prohibited text. Continue the same role and run. Reject prohibited owner input and source metadata at their existing boundaries.
10. After both kinds of omission, check whether the remaining answer has substantive text **excluding the omission markers**. A response consisting only of prohibited prose or a disallowed URL is not a successful contribution. Give the same role/task one bounded correction attempt for either condition, without repeating already confirmed contributions or fabricating a Head task or consultant conclusion. Distinguish unusable language from unusable link-only output and from a genuinely empty provider response; do not label every unsafe link a language violation. If the correction is also unusable, save a truthful System notice explaining that no usable answer remained, preserve the question, and let Retry resume the missing step. System notices and rejected drafts must not become business context. Log only output kind, policy reason and omission count, never rejected words, URLs or private prompt text.

## Acceptance probes

- A fixed-size run and an Auto run show Head choosing exact roles. A long, unusual, non-imperative Head task reaches only its chosen recipient byte-for-byte in one call; no generic fallback appears.
- Every role receives the first and latest owner messages plus a discussion longer than the former 80,000-character window. A long requested final survives history and export intact.
- A Critic stop-and-rework names a specific unsupported claim, missing owner output or false number and produces an actual correction or evidence-based objection; a sound consultant draft receives no invented defect. Head closes after one productive review in a higher-ceiling setting, but can continue when a specific issue remains; no repeated filler. Failure or Stop after a Critic challenge resumes at the missing reply without duplicate work. A saved former-version task roster resumes with its exact committed prefix.
- Mixed generated output with a Russian/Belarusian sentence keeps useful English/Ukrainian text and completes the consultation; test a guilty sentence containing a URL and one in a multiline reply so no prohibited remainder leaks. An unsuitable generated Markdown or raw URL is visibly omitted and absent from source records. Test both provider adapters. Confirm valid Ukrainian and English language descriptors survive owner input, provider output and source-title/claim checks.
- An answer containing only a disallowed URL, only prohibited-language prose, or only omission markers is not accepted as useful work. Each policy-invalid case gets exactly one same-role correction; a genuinely empty provider completion is reported separately. Verify a successful correction completes the run with no System error, and a second unusable result preserves the question with a truthful Retry action. Confirm saved System notices and discarded drafts never enter subsequent agent context, private logs contain only omission counts/reasons, and Stop/Retry does not replay the confirmed prefix.
- Migrate old public Critic challenge and final-review defaults while retaining owner-customized text and prior encrypted revisions. Check that both old accepted-run snapshots and new runs still instruct Critic to identify concrete unsupported claims or missing owner outputs; a sound position does not receive an invented objection.
- A public numeric article URL remains researchable even when the owner request separately contains a private phone number. Inspect the web-enabled provider's actual prompt to prove it contains only a safe public query. Unsafe query material is withheld, and more than eight valid direct sources remain inspectable.
- The final answer identifies every synthetic requested output, cites direct evidence and explicitly names anything unavailable. Browser Settings text matches the new ceiling semantics. Run the target's full automated suite, real browser checks and actual provider probe separately; report untested platforms/devices honestly.

Do not copy private records, production credentials, public URLs from a real owner conversation, local absolute paths, the encrypted database or an existing SDD manifest between repositories. The target's deployment mechanism, data retention, network trust and source-policy decisions remain its own authorities.
